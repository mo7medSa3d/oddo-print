# Direct Odoo Agent & License API

This document describes the active print data-plane API (served by the Odoo 19 `print_gateway` addon) and the License-Only Gateway control-plane API (served by Yaseir Cloud).

## Print Data-Plane Authentication (Odoo)

After pairing, the Agent sends:

```http
Authorization: Bearer <agent-uid>:<agent-token>
```

The token is generated by Odoo during pairing. Only a hash is stored in the Odoo agent record; the raw value is held by the Agent's protected local credential store.

## Direct Odoo Agent Endpoints

### `GET /api/agent/probe`

Public readiness probe. Expected response:

```json
{"ok":true,"service":"odoo-direct-print-agent"}
```

### `POST /api/agent/register`

Consumes an Odoo-generated, unexpired six-character pairing code. Returns `agentId`, `token`/`secret`, company scope and the current signed license bundle where available. Pairing codes must be reissued when credential material changes.

### `GET /api/agent/ws`

Authenticated RFC 6455 WebSocket upgrade endpoint served directly by Odoo (`odoo_addons/print_gateway/controllers/agent_ws.py`). Odoo listens on PostgreSQL `LISTEN print_gateway_job_ready` (emitted via `pg_notify('print_gateway_job_ready', ...)` when a print job is queued) and pushes immediate wake-up notifications to the connected Agent so it claims jobs without waiting for the polling interval. If the WebSocket upgrade is unavailable or disconnects, the Agent automatically falls back to authenticated HTTP polling.

### `POST /api/agent/heartbeat`

Authenticated presence and inventory update. The Agent sends its local printer snapshot and `keepAliveJobIds`. Odoo updates the Agent's last-seen timestamp and upserts the Agent-owned printer records.

### `GET /api/agent/jobs`

Authenticated pull/claim endpoint (also used as the automatic fallback when `/api/agent/ws` is unavailable). Odoo uses a database transaction and `FOR UPDATE SKIP LOCKED` to claim eligible queued jobs for printers owned by this Agent. Response is a JSON array. Each item contains the job ID, printer ID, payload metadata and claim token.

### `POST /api/agent/ack`

Authenticated state acknowledgement. The request includes `jobId`, `claimToken` and one of these statuses:

- `queued`: release a claim only when the job has not crossed into `printing`.
- `printing`: acknowledge the physical execution boundary before touching the printer.
- `success`: Agent execution completed; this is not independent paper-output proof.
- `failed`: execution failed; error details are retained in Odoo.

A stale or mismatched claim token is rejected. Once a job is `printing`, it is not automatically returned to `queued` after an uncertain failure.

## Transport and timing

- Production transport: HTTPS / WSS (direct Odoo ↔ Agent; no Cloud relay).
- Job acquisition: RFC 6455 WebSocket push (`/api/agent/ws`) with automatic HTTP polling fallback every 5 seconds (`/api/agent/jobs`).
- Heartbeat: every 30 seconds.
- Odoo claim lease: 90 seconds.
- The Agent initiates all outbound connections; no inbound workstation port is required.

## License-Only Gateway API (Yaseir Cloud)

The Next.js Cloud Gateway is strictly a subscription, tenant, and licensing control plane. Legacy `/api/printers` routes and `/platform/operations` have been removed; Cloud never creates, claims, dispatches, or reconciles print jobs.

### `POST /api/license/refresh`

Authenticated license issuance endpoint. Accepts `{ "odooDbUuid": "<uuid>", "tenantId": "<optional>" }` and returns an Ed25519 v2 signed license bundle (`payload` + base64url `signature`) containing `version`, `rev` (monotonic anti-rollback revision), `status` (`active` or `revoked`), `license_id`, `tenant_id`, `odoo_db_uuid`, `plan`, `max_agents`, `max_printers`, `issued_at`, `expires_at`, and `grace_until`.

### `POST /api/license/verify`

Verifies an Ed25519 v1/v2 signed license bundle against the Gateway's public key, checking cryptographic signature integrity, `odoo_db_uuid` binding, `status` (rejecting `revoked`), `minRev` anti-rollback protection, expiry, and grace period.
